What differences do you observe in the metadata and generated bytecode compared to the previous version of the Student class in Kotlin?

    - `0: aload_0`;
    - ``1: invokespecial #8 // Method Person."<init>":()V``;
    - `4: nop` in Kotlin and not in Java;
    - `5: return` in Kotlin and `4: return` in Java.

15. **Given the observations what is the difference between the generated bytecode of a java class constructor and a kotlin class initializer? Why?**  
R -> In Java the `init` block does not exist, so only the constructor is compiled into bytecode. Otherwise, in Kotlin, the `init` block is declared and compiled as part of the constructor. Even tho it is empty, the compiler still count it as a initialization code, giving it the bytecode: `nop`.

# Part 3: Kotlin to Java type system
**Account.kt**:
```
class Account(var Balance: Long) {

}
```
3. **Use the javap tool to inspect the generated metadata: javap -p Account.class.**  
The -p flag is used to show private members.  
What is the name, kind and signature of each member of the Account class?  
R -> 
    - ``Balance`` - Type: `Field` and Signature: ``private long Balance;``
    - ``Account`` - Type: `Constructor` and Signature: ``public Account(long);``
    - ``getBalance`` - Type: `Method (getter)` and Signature: ``public final long getBalance();``
    - ``setBalance`` - Type: `Method (setter)` and Signature: ``public final void setBalance(long);``

4. **Create a Java source file named Account.java with the equivalent definition to the Account class in Kotlin.**  
Confirm that the generated metadata of the Java class is equivalent to the one generated for the Kotlin class.  
R -> ``Account.java``:
    ```
    public class Account {
        private long balance;

        public Account(long balance) {
            this.balance = balance;
        }

        public long getBalance() {
            return balance;
        }

        public void setBalance(long balance) {
            this.balance = balance;
        }
    }
    ```
    And it's metadata is:
    ```
    Compiled from "Account.java"
    public class Account {
        public Account(long);
        public long getBalance();
        public void setBalance(long);
    }
    ```
    Unlike Kotlin, Java doesn't automatically generate methods, so we need to define them: `getBalance()` and `setBalance()`.
